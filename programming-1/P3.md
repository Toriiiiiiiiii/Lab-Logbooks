### Sec 3.1.2
An appropriate type to represent dates would perhaps be a tuple of `int`s: eg `(5, 1, 2026)` to represent the 5th of January 2026. Similarly, a tuple of 2 `int`s might be appropriate to represent a time, eg `(16, 27)` for 4:27pm.

```py
# UK-Format Date
print(f'{now:%d/%m/%Y}')

# US-Format Date
print(f'{now:%m/%d/%Y}')
```

* The ISO-8601 format removes the ambiguity of numbered dates (such as the switching of day and month in the British/American formats). By doing this, there is no guesswork involved for a human (or computer) as to which number represents which field.

* The `%y` operator resolves to the year, as a 2-character 0 padded string, without the century or millenium. The `%Y` operator resolves to the year as a 4-character 0 padded string, including the century and millenium.
* Zero-Padded strings are numbers that are formatted to print zeros before the string to a certain length. For example, if the number 24 were printed as a 4-character 0 padded string, it would display as `'0024'`.

* I would expect `delta + delta` and `now + now` to work, as they are operating on the same type. I would expect `now + delta` to not work, as they are different types.
* I was surprised to find out that the `+` operator is not valid for two `datetime` objects, but is valid between a `datetime` and `timedelta` object.
